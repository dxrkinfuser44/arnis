📋 Overview

Element processing is the core transformation engine of Arnis. It takes parsed OSM data (nodes, ways, and relations) and converts them into Minecraft blocks. Each type of real-world feature (buildings, roads, water, etc.) has a dedicated processor module that handles its specific generation logic.

🎯 Goal: Transform abstract OSM tags and coordinates into tangible Minecraft structures that accurately represent real-world features while maintaining good performance and visual quality.

⚡ Priority System

Elements are processed in a specific order to ensure correct layering. Features processed later can overwrite earlier ones, so the priority system is crucial for visual accuracy.

Priority Order

1. Entrance (Highest)
2. Building
3. Highway
4. Waterway
5. Water
6. Barrier (Lowest)

Priority Rationale

Priority Element Type Reasoning
1 Entrances/Doors Must be placed last to prevent being overwritten by walls or roads
2 Buildings Large structures that should overlay most terrain features
3 Highways Roads connect buildings and should be visible, but not cover structures
4 Waterways Linear water features like rivers
5 Water Areas Large water bodies serve as base terrain
6 Barriers Walls and fences are processed early as boundary features 
// Priority
implementation const PRIORITY_ORDER: [&str; 6] = [ "entrance", "building", "highway", "waterway", "water", "barrier", ]; pub fn get_priority(element: &ProcessedElement) -> usize { for (i, &tag) in PRIORITY_ORDER.iter().enumerate() { if element.tags().contains_key(tag) { return i; } } PRIORITY_ORDER.len() // Default priority for unmatched elements } // Sort elements before processing elements.sort_by_key(|element| get_priority(element));
⚠️ Priority Conflicts: When an element has multiple tags from different priority levels, the highest priority (lowest number) takes precedence.

🧮 Core Algorithms

Building Generation

Building generation is one of the most complex processors, handling multiple roof types, materials, and interior layouts.

Algorithm Steps

  1. Parse building outline from way or relation nodes
  2. Determine height from tags or estimate based on levels
  3. Select materials based on building:material tag
  4. Generate walls along the outline
  5. Create floors for multi-story buildings
  6. Generate roof based on roof:shape tag
  7. Add interior (if enabled) with rooms and stairs
  8. Handle courtyards (inner ways in multipolygon)
// Building generation example
pub fn generate_buildings(
    editor: &mut WorldEditor,
    way: &ProcessedWay,
    args: &Args,
    override_material: Option,
) {
    // Extract tags
    let height = estimate_height(&way.tags);
    let material = select_material(&way.tags, override_material);
    let roof_shape = way.tags.get("roof:shape");

    // Get bounding box
    let (min_x, max_x, min_z, max_z) = get_bounds(&way.nodes);

    // Generate walls
    for node_window in way.nodes.windows(2) {
        draw_wall(editor, &node_window[0], &node_window[1], height, material);
    }

    // Generate floors
    if args.interior && height > 3 {
        generate_interior(editor, way, height, material);
    }

    // Generate roof
    if args.roof {
        let roof_type = parse_roof_type(roof_shape);
        generate_roof(editor, roof_type, min_x, max_x, min_z, max_z, height);
    }
}

Roof Generation

Arnis supports multiple roof types with different generation algorithms:

Gabled Roof

// Two sloping sides meeting at a ridge
fn generate_gabled_roof(
    editor: &mut WorldEditor,
    min_x: i32, max_x: i32,
    min_z: i32, max_z: i32,
    base_height: i32,
    roof_height: i32,
    roof_block: Block,
) {
    let width = max_x - min_x;
    let ridge_offset = width / 2;

    for x in min_x..=max_x {
        let distance_from_center = (x - min_x - ridge_offset).abs();
        let slope_height = roof_height - (distance_from_center * roof_height / ridge_offset);

        for z in min_z..=max_z {
            let y = base_height + slope_height;
            editor.set_block(roof_block, x, y, z, None, None);
        }
    }
}

Pyramidal Roof

// All sides slope to a central point
fn generate_pyramidal_roof(
    editor: &mut WorldEditor,
    min_x: i32, max_x: i32,
    min_z: i32, max_z: i32,
    base_height: i32,
    roof_height: i32,
    roof_block: Block,
) {
    let center_x = (min_x + max_x) / 2;
    let center_z = (min_z + max_z) / 2;

    for y_offset in 0..roof_height {
        let shrink = y_offset;

        for x in (min_x + shrink)..=(max_x - shrink) {
            for z in (min_z + shrink)..=(max_z - shrink) {
                let y = base_height + y_offset;
                editor.set_block(roof_block, x, y, z, None, None);
            }
        }
    }
}

Water Area Flood-Fill

Water bodies use a flood-fill algorithm to fill enclosed areas. This is essential for correctly rendering lakes and oceans with islands. 

pub fn flood_fill_water(
    editor: &mut WorldEditor,
    start_x: i32,
    start_z: i32,
    boundary: &HashSet<(i32, i32)>,
    timeout: Option,
) {
    let start_time = Instant::now();
    let mut queue = VecDeque::new();
    let mut visited = HashSet::new();

    queue.push_back((start_x, start_z));

    while let Some((x, z)) = queue.pop_front() {
        // Check timeout
        if let Some(t) = timeout {
            if start_time.elapsed() > t {
                eprintln!("Flood-fill timeout reached");
                break;
            }
        }

        // Skip if already visited or on boundary
        if visited.contains(&(x, z)) || boundary.contains(&(x, z)) {
            continue;
        }

        visited.insert((x, z));

        // Place water block
        editor.set_block(WATER, x, 0, z, None, None);

        // Add neighbors to queue
        for (dx, dz) in [(-1, 0), (1, 0), (0, -1), (0, 1)] {
            queue.push_back((x + dx, z + dz));
        }
    }
}
✅ Optimization: The flood-fill algorithm uses a timeout to prevent infinite loops in case of errors or extremely large water bodies.

Highway Connectivity

The highway processor builds a connectivity graph to detect intersections and ensure roads connect properly. 

pub fn build_highway_connectivity_map(
    elements: &[ProcessedElement]
) -> HashMap> {
    let mut connectivity: HashMap> = HashMap::new();

    for element in elements {
        if let ProcessedElement::Way(way) = element {
            if !way.tags.contains_key("highway") {
                continue;
            }

            // Connect each node to its neighbors in the way
            for window in way.nodes.windows(2) {
                let node1_id = window[0].id;
                let node2_id = window[1].id;

                connectivity.entry(node1_id)
                    .or_default()
                    .push(node2_id);

                connectivity.entry(node2_id)
                    .or_default()
                    .push(node1_id);
            }
        }
    }

    connectivity
}

Bresenham's Line Algorithm

Used for drawing straight lines between nodes (roads, walls, etc.) efficiently. 

pub fn bresenham_line(
    x0: i32, z0: i32,
    x1: i32, z1: i32
) -> Vec<(i32, i32)> {
    let mut points = Vec::new();

    let dx = (x1 - x0).abs();
    let dz = (z1 - z0).abs();
    let sx = if x0 < x1 { 1 } else { -1 };
    let sz = if z0 < z1 { 1 } else { -1 };
    let mut err = dx - dz;

    let mut x = x0;
    let mut z = z0;

    loop {
        points.push((x, z));

        if x == x1 && z == z1 {
            break;
        }

        let e2 = 2 * err;
        if e2 > -dz {
            err -= dz;
            x += sx;
        }
        if e2 < dx {
            err += dx;
            z += sz;
        }
    }

    points
}

Material Selection Logic

fn select_building_material(tags: &HashMap) -> Block {
    // Check explicit material tag
    if let Some(material) = tags.get("building:material") {
        return match material.as_str() {
            "brick" => BRICK,
            "wood" => OAK_PLANKS,
            "concrete" | "cement" => CONCRETE,
            "stone" => STONE,
            "glass" => GLASS,
            "metal" => IRON_BLOCK,
            _ => STONE,  // Default
        };
    }

    // Infer from building type
    if let Some(building_type) = tags.get("building") {
        return match building_type.as_str() {
            "house" | "residential" => OAK_PLANKS,
            "commercial" | "retail" => BRICK,
            "industrial" => IRON_BLOCK,
            "church" | "cathedral" => STONE_BRICKS,
            _ => STONE,
        };
    }

    STONE  // Fallback default
}

Roof Material Selection

fn select_roof_material(
    tags: &HashMap,
    wall_block: Block
) -> Block {
    // Check explicit roof material
    if let Some(roof_mat) = tags.get("roof:material") {
        return match roof_mat.as_str() {
            "tiles" | "tile" => RED_TERRACOTTA,
            "slate" => GRAY_TERRACOTTA,
            "metal" => IRON_BLOCK,
            "thatch" => HAY_BLOCK,
            "concrete" => GRAY_CONCRETE,
            _ => BRICK,
        };
    }

    // Check roof color
    if let Some(color) = tags.get("roof:colour") {
        if let Some(block) = color_to_block(color) {
            return block;
        }
    }

    // Default: use wall material or brick
    match wall_block {
        OAK_PLANKS => OAK_LOG,
        BRICK => BRICK,
        STONE => STONE_BRICK_SLAB,
        _ => BRICK,
    }
}

✨ Best Practices

Performance Optimization

  • Batch Operations: Use fill_blocks() instead of individual set_block() calls when possible
  • Early Returns: Check for invalid data and return early to avoid unnecessary processing
  • Caching: Store expensive calculations (like connectivity maps) rather than recalculating
  • Bbox Clipping: Only process elements within the generation area

Code Organization

  • Single Responsibility: Each processor should handle one category of features
  • Helper Functions: Extract common logic into reusable functions
  • Clear Naming: Use descriptive names for functions and variables
  • Documentation: Comment complex algorithms and tag mappings

Error Handling

  • Graceful Degradation: Handle missing tags with sensible defaults
  • Validation: Check data ranges before processing
  • Logging: Warn about unusual situations without stopping generation
  • Timeouts: Implement timeouts for potentially infinite loops (like flood-fill)
💡 Tip: When adding a new processor, start by copying an existing one with similar complexity and adapt it to your needs. This ensures consistent code style and proper error handling.
