📖 Overview

World generation is the final stage of the Arnis pipeline, where all processed elements and terrain data are serialized into Minecraft world files. Arnis supports both Java Edition (Anvil format) and Bedrock Edition (LevelDB format), each with different file structures and serialization requirements.

🎯 Key Responsibility: The world generation system manages block placement, chunk organization, region files, and NBT (Named Binary Tag) serialization to create valid, playable Minecraft worlds.

Generation Pipeline

📦 World Formats

☕ Java Edition (Anvil)

File Structure

world/
├── level.dat          # World metadata
├── level.dat_old      # Backup metadata
├── session.lock       # Lock file
├── region/            # Region files
│   ├── r.0.0.mca     # Region (0,0)
│   ├── r.0.1.mca     # Region (0,1)
│   └── ...
└── playerdata/        # Player data
    └── ...

Key Features

  • Region Files: .mca files containing 32×32 chunks
  • NBT Format: Hierarchical named binary tags
  • Chunk Size: 16×384×16 blocks (1.18+)
  • Compression: Zlib or GZip

Coordinates

  • Y Range: -64 to 319
  • Chunk Coordinates: Block coords / 16
  • Region Coordinates: Chunk coords / 32

🪨 Bedrock Edition

File Structure

world/
├── level.dat          # World metadata
├── levelname.txt      # World name
├── db/                # LevelDB database
│   ├── MANIFEST-*
│   ├── *.ldb          # Data tables
│   └── *.log
└── ...

Key Features

  • LevelDB: Key-value database for chunks
  • MCWorld Format: Zip archive for distribution
  • Chunk Size: 16×256×16 blocks
  • Compression: None or Zlib

Coordinates

  • Y Range: -64 to 319 (newer versions)
  • Chunk Keys: Binary keys in database
  • Subchunks: 16-block tall sections

Format Comparison

Feature Java Edition Bedrock Edition
Storage Region files (.mca) LevelDB database
Compression Zlib/GZip Optional Zlib
Distribution Folder .mcworld (zip)
Block IDs String namespaces String + state properties
Performance Fast region access Fast chunk access

🔧 WorldEditor API

The WorldEditor is Arnis's abstraction layer for world file management. It provides a unified API for both Java and Bedrock formats, handling all the complexity of file formats, coordinate systems, and serialization.

Core Structure

pub struct WorldEditor<'a> {
    world_dir: PathBuf,
    world: Box,
    xzbbox: XZBBox,
    llbbox: LLBBox,
    ground: Option<&'a Ground>,
    format: WorldFormat,
    // Bedrock-specific fields
    bedrock_level_name: Option,
    bedrock_spawn_point: Option<(i32, i32)>,
}

pub enum WorldFormat {
    JavaAnvil,
    BedrockMcWorld,
}

Block Placement Methods

Relative Block Placement

// Place block relative to ground level
pub fn set_block(
    &mut self,
    block: Block,
    x: i32,
    y_offset: i32,  // Offset from ground level
    z: i32,
    replace: Option<&[Block]>,
    ignore: Option<&[Block]>,
) {
    // Convert relative Y to absolute Y using ground data
    let abs_y = self.get_absolute_y(x, y_offset, z);
    self.set_block_absolute(block, x, abs_y, z, replace, ignore);
}

// Example usage
editor.set_block(STONE, 100, 5, 200, None, None);
// Places stone at 5 blocks above ground at (100, 200)

Absolute Block Placement

// Place block at absolute world coordinate
pub fn set_block_absolute(
    &mut self,
    block: Block,
    x: i32,
    y: i32,  // Absolute world Y coordinate
    z: i32,
    replace: Option<&[Block]>,
    ignore: Option<&[Block]>,
) {
    // Validate coordinates
    if !self.is_valid_position(x, y, z) {
        return;
    }

    // Check replacement rules
    if let Some(current) = self.block_at_absolute(x, y, z) {
        if let Some(ignore_list) = ignore {
            if ignore_list.contains(¤t) {
                return;
            }
        }
        if let Some(replace_list) = replace {
            if !replace_list.contains(¤t) {
                return;
            }
        }
    }

    // Place block
    self.world.set_block(x, y, z, block);
}

// Example usage
editor.set_block_absolute(BEDROCK, 100, -64, 200, None, None);
// Places bedrock at absolute Y=-64

Bulk Operations

// Fill volume with blocks (relative coordinates)
pub fn fill_blocks(
    &mut self,
    block: Block,
    x1: i32, y1: i32, z1: i32,
    x2: i32, y2: i32, z2: i32,
    replace: Option<&[Block]>,
    ignore: Option<&[Block]>,
) {
    for x in x1.min(x2)..=x1.max(x2) {
        for y in y1.min(y2)..=y1.max(y2) {
            for z in z1.min(z2)..=z1.max(z2) {
                self.set_block(block, x, y, z, replace, ignore);
            }
        }
    }
}

Query Methods

// Check if specific block(s) exist at position
pub fn check_for_block(
    &self,
    x: i32, y: i32, z: i32,
    blocks: Option<&[Block]>,
) -> bool {
    let abs_y = self.get_absolute_y(x, y, z);
    self.check_for_block_absolute(x, abs_y, z, blocks)
}

// Get block at position
pub fn block_at_absolute(
    &self,
    x: i32, y: i32, z: i32
) -> Option {
    if !self.is_valid_position(x, y, z) {
        return None;
    }
    self.world.get_block(x, y, z)
}

// Example usage
if editor.check_for_block(x, 0, z, Some(&[STONE, DIRT])) {
    println!("Found stone or dirt at ground level");
}

Coordinate Conversion

// Convert relative Y to absolute Y
pub fn get_absolute_y(&self, x: i32, y_offset: i32, z: i32) -> i32 {
    if let Some(ground) = self.ground {
        // Use elevation data if available
        let elevation = ground.get_height(x, z);
        ground.ground_level + elevation + y_offset
    } else {
        // Use default ground level
        DEFAULT_GROUND_LEVEL + y_offset
    }
}

// Get coordinate bounds
pub fn get_min_coords(&self) -> (i32, i32) {
    (self.xzbbox.min_x(), self.xzbbox.min_z())
}

pub fn get_max_coords(&self) -> (i32, i32) {
    (self.xzbbox.max_x(), self.xzbbox.max_z())
}

Saving Worlds

// Save world to disk
pub fn save(&mut self) {
    match self.format {
        WorldFormat::JavaAnvil => {
            self.world.save();
            self.save_metadata();
        }
        WorldFormat::BedrockMcWorld => {
            self.save_bedrock();
        }
    }
}

// Save metadata (level.dat)
fn save_metadata(&self) -> Result<(), Box> {
    let metadata = WorldMetadata {
        min_mc_x: self.xzbbox.min_x(),
        max_mc_x: self.xzbbox.max_x(),
        min_mc_z: self.xzbbox.min_z(),
        max_mc_z: self.xzbbox.max_z(),
        min_geo_lat: self.llbbox.min().lat(),
        max_geo_lat: self.llbbox.max().lat(),
        min_geo_lon: self.llbbox.min().lng(),
        max_geo_lon: self.llbbox.max().lng(),
    };

    // Write to .arnis-metadata.json
    let json = serde_json::to_string_pretty(&metadata)?;
    fs::write(self.world_dir.join(".arnis-metadata.json"), json)?;
    Ok(())
}

use serde::{Serialize, Deserialize};

🗺️ Region Files

Region Structure

Java Edition uses region files (.mca) that contain 32×32 chunks. Each region file covers a 512×512 block area. 

// Region file naming
r.X.Z.mca  // Where X and Z are region coordinates

// Examples:
r.0.0.mca   // Chunks (0,0) to (31,31)
r.-1.0.mca  // Chunks (-32,0) to (-1,31)
r.1.-2.mca  // Chunks (32,-64) to (63,-33)

// Calculate region coordinates
region_x = floor(chunk_x / 32)
region_z = floor(chunk_z / 32)

// Calculate chunk coordinates
chunk_x = floor(block_x / 16)
chunk_z = floor(block_z / 16)

Region File Format

// Region file structure
+------------------+
| Locations (4KB)  |  // 1024 chunk offsets (3 bytes) + sizes (1 byte)
+------------------+
| Timestamps (4KB) |  // 1024 chunk timestamps (4 bytes each)
+------------------+
| Chunk Data       |  // Compressed NBT chunk data
+------------------+

Using FastAnvil

use fastanvil::{Region, JavaChunk};

// Open region file
let mut region = Region::from_file("world/region/r.0.0.mca")?;

// Read chunk
let chunk_data = region.read_chunk(0, 0)?;
let chunk: JavaChunk = fastnbt::from_bytes(&chunk_data)?;

// Write chunk
region.write_chunk(0, 0, &chunk_data)?;

⛰️ Ground Generation

After all features are placed, Arnis fills the ground layers with grass, dirt, stone, and bedrock.

Ground Layers

Grass Block (Y=0)
Dirt (Y=-1)
Dirt (Y=-2)
Stone (Y=-3 to Y=-63)
Bedrock (Y=-64)

Generation Code

// Ground generation loop
for x in xzbbox.min_x()..=xzbbox.max_x() {
    for z in xzbbox.min_z()..=xzbbox.max_z() {
        // Place surface layer
        if !editor.check_for_block(x, 0, z, Some(&[STONE])) {
            editor.set_block(GRASS_BLOCK, x, 0, z, None, None);
            editor.set_block(DIRT, x, -1, z, None, None);
            editor.set_block(DIRT, x, -2, z, None, None);
        }

        // Fill underground with stone
        if args.fillground {
            editor.fill_blocks_absolute(
                STONE,
                x, MIN_Y + 1, z,
                x, editor.get_absolute_y(x, -3, z), z,
                None, None
            );
        }

        // Place bedrock at bottom
        editor.set_block_absolute(
            BEDROCK, x, MIN_Y, z,
            None, Some(&[BEDROCK])
        );
    }
}

⚡ Performance Optimization

Bulk Operations

  • Use fill_blocks() instead of loops of set_block()
  • Batch chunk writes to reduce I/O operations
  • Minimize redundant coordinate conversions

Memory Management

  • Process regions sequentially to avoid loading entire world into memory
  • Release chunk data after writing to disk
  • Use streaming for large areas

Parallel Processing

use rayon::prelude::*;

// Parallel ground generation (per X column)
(min_x..=max_x).into_par_iter().for_each(|x| {
    for z in min_z..=max_z {
        // Generate ground for this column
        // Each thread works on different X columns
    }
});
✅ Best Practice: For very large worlds, process in chunks and release memory between chunks to avoid running out of RAM.

✨ Best Practices

Error Handling

  • Always validate coordinates before block placement
  • Check world format compatibility when using format-specific features
  • Handle file I/O errors gracefully
  • Use Result types for operations that can fail

Session Locking

// Lock world to prevent Minecraft from opening it during generation
struct SessionLock {
    file: fs::File,
    path: PathBuf,
}

impl SessionLock {
    fn acquire(world_path: &Path) -> Result {
        let path = world_path.join("session.lock");
        let file = fs::File::create(&path)?;
        file.try_lock_exclusive()?;
        Ok(SessionLock { file, path })
    }
}

impl Drop for SessionLock {
    fn drop(&mut self) {
        let _ = self.file.unlock();
        let _ = fs::remove_file(&self.path);
    }
}

Testing

  • Test with small areas before processing large regions
  • Verify worlds load correctly in Minecraft
  • Check for missing chunks or corrupted data
  • Validate NBT structure with external tools
⚠️ Warning: Always backup existing worlds before modifying them. World file corruption can result in loss of player data and builds.
