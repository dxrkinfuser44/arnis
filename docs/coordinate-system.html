🌍 Overview

Arnis uses a sophisticated coordinate transformation

system to convert real-world geographic coordinates into Minecraft block coordinates. This system is the foundation of accurate world generation, ensuring that the spatial relationships in OpenStreetMap data are preserved in the generated Minecraft world.

📍 Key Concept: The coordinate system bridges two fundamentally different spaces: geographic coordinates (spherical, in degrees) and Minecraft coordinates (Cartesian, in blocks). Understanding this transformation is crucial for working with Arnis.

Two Coordinate Systems

🌐 Geographic Coordinates

System: WGS84 (EPSG:4326)

Units: Degrees

Components:

  • 📍 Latitude (lat) - North/South
  • 📍 Longitude (lng) - East/West

Range:

lat: -90° to 90°
lng: -180° to 180°

🎮 Minecraft Coordinates

System: Cartesian

Units: Blocks

Components:

  • 🔷
    • X - East/West
  • 🔷 Y - Up/Down (elevation)
  • 🔷 Z - North/South

Range:

x, z: -30,000,000 to 30,000,000
y: -64 to 319

🗺️ Geographic Coordinate System

WGS84 Standard

OpenStreetMap uses the WGS84 coordinate reference system (EPSG:4326), which represents locations on Earth using latitude and longitude in decimal degrees.

Latitude (lat)
  • Range: -90° (South Pole) to +90° (North Pole)
  • Zero point: Equator
  • Positive: Northern Hemisphere
  • Negative: Southern Hemisphere

Longitude (lng)

  • Range: -180° (Western) to +180° (Eastern)
  • Zero point: Prime Meridian (Greenwich)
  • Positive: East of Prime Meridian
  • Negative: West of Prime Meridian

Bounding Boxes

A bounding box (bbox) defines a rectangular geographic area using minimum and maximum coordinates: 

//
LLBBox structure pub struct LLBBox { min: LLPoint, // Southwest corner (min_lat, min_lng) max: LLPoint, // Northeast corner (max_lat, max_lng) } // Example: Central London let bbox = LLBBox { min: LLPoint::new(51.500, -0.130), // min_lat, min_lng max: LLPoint::new(51.520, -0.100), // max_lat, max_lng };
⚠️ Important: Longitude values can wrap around at ±180°. Areas crossing the International Date Line require special handling. Arnis currently works best with bounding boxes that don't cross this line.

Geographic Point Structure

// LLPoint (Lat/Lng Point)
pub struct LLPoint {
    lat: f64,  // Latitude in degrees
    lng: f64,  // Longitude in degrees
}

impl LLPoint {
    pub fn new(lat: f64, lng: f64) -> Result {
        // Validate ranges
        if lat < -90.0 || lat > 90.0 {
            return Err("Latitude out of range");
        }
        if lng < -180.0 || lng > 180.0 {
            return Err("Longitude out of range");
        }
        Ok(Self { lat, lng })
    }
}

🎮 Minecraft Coordinate System

Cartesian Coordinates

Minecraft uses a 3D Cartesian coordinate system with integer block positions. Arnis primarily works with X and Z coordinates (horizontal plane), while Y represents elevation.

X-Axis (East/West)

  • Direction: Increases toward East, decreases toward West
  • Range: -30,000,000 to 30,000,000 (world border)
  • Unit: 1 block

Y-Axis (Up/Down)

  • Direction: Increases upward, decreases downward
  • Range: -64 (deepslate) to 319 (build limit)
  • Ground level: Configurable (default: -62 in Arnis)
  • Bedrock: Y = -64

Z-Axis (North/South)

  • Direction: Increases toward South, decreases toward North
  • Range: -30,000,000 to 30,000,000
  • Unit: 1 block
🧭 Cardinal Directions: In Minecraft, negative X is West, positive X is East, negative Z is North, and positive Z is South. This is important when orienting real-world geographic data.

XZPoint Structure

// XZPoint (Minecraft horizontal coordinates)
pub struct XZPoint {
    pub x: i32,  // East/West position in blocks
    pub z: i32,  // North/South position in blocks
}

// XZBBox (Minecraft bounding box)
pub struct XZBBox {
    min_x: i32,
    max_x: i32,
    min_z: i32,
    max_z: i32,
}

impl XZBBox {
    pub fn width(&self) -> i32 {
        self.max_x - self.min_x + 1
    }

    pub fn height(&self) -> i32 {
        self.max_z - self.min_z + 1
    }

    pub fn total_blocks(&self) -> u64 {
        (self.width() as u64) * (self.height() as u64)
    }
}

Relative vs Absolute Y Coordinates

Arnis uses two types of Y coordinates:

Type Description Use Case
Relative Y Offset from ground level (e.g., y=0 is ground, y=10 is 10 blocks above) Buildings, vegetation, structures
Absolute Y Fixed world coordinate (e.g., y=-64 is bedrock, y=0 is sea level) Terrain, bedrock, elevation-based features 
// WorldEditor methods
editor.set_block(STONE, x, 5, z, None, None);  // Relative: 5 blocks above ground

editor.set_block_absolute(BEDROCK, x, -64, z, None, None);  // Absolute: bedrock layer

Transformation Formulas

Longitude to X (East/West)

x = (lng - min_lng) × scale_factor_x × scale

Where scale_factor_x is calculated based on the distance between min and max longitude, converted to meters at the given latitude.

Latitude to Z (North/South)

z = (max_lat - lat) × scale_factor_z × scale

Note the inversion: higher latitudes (North) map to lower Z values in Minecraft.

Scale Factor Calculation

The scale factor converts degrees to meters, accounting for Earth's curvature: 

// Earth's radius in meters
const EARTH_RADIUS: f64 = 6371000.0;

// Latitude to meters (constant at all latitudes)
let lat_diff_rad = (max_lat - min_lat).to_radians();
let meters_per_degree_lat = EARTH_RADIUS * lat_diff_rad / (max_lat - min_lat);

// Longitude to meters (varies with latitude)
let avg_lat = (min_lat + max_lat) / 2.0;
let lng_diff_rad = (max_lng - min_lng).to_radians();
let meters_per_degree_lng = EARTH_RADIUS * avg_lat.cos() * lng_diff_rad / (max_lng - min_lng);

// Scale factors (meters to blocks)
scale_factor_x = meters_per_degree_lng;
scale_factor_z = meters_per_degree_lat;
⚠️ Latitude Dependency: The meters-per-degree for longitude varies with latitude. At the equator, one degree of longitude ≈ 111 km. At 60° latitude, it's only ≈ 56 km. Arnis uses the average latitude of the bounding box for this calculation.

User Scale Parameter

The user can specify a scale parameter that multiplies the final coordinates:

  • scale = 1.0: 1 real-world meter = 1 Minecraft block (default)
  • scale = 2.0: 1 real-world meter = 2 Minecraft blocks (2x larger)
  • scale = 0.5: 2 real-world meters = 1 Minecraft block (2x smaller)
// CLI usage
cargo run -- --bbox="51.5,0.1,51.6,0.2" --scale=2.0 --path="/path/to/world"

Complete Transformation Example

Scenario: Transform London coordinates

// Input bounding box
let llbbox = LLBBox {
    min: LLPoint::new(51.500, -0.130),
    max: LLPoint::new(51.520, -0.100),
};
let scale = 1.0;

// Create transformer
let (transformer, xzbbox) = CoordTransformer::llbbox_to_xzbbox(&llbbox, scale)?;

// Transform a specific point (Big Ben)
let big_ben = LLPoint::new(51.5007, -0.1246);
let mc_point = transformer.transform_point(big_ben);

// Result
println!("Big Ben in Minecraft: x={}, z={}", mc_point.x, mc_point.z);
// Output: x=169, z=43 (approximate, relative to bbox minimum)

📦 Bounding Box Operations

Clipping

Clipping is a critical optimization that reduces the number of nodes processed by removing those outside the bounding box. 

pub fn clip_way_to_bbox(
    nodes: &[ProcessedNode],
    bbox: &XZBBox
) -> Vec {
    let mut clipped = Vec::new();

    for window in nodes.windows(2) {
        let p1 = &window[0];
        let p2 = &window[1];

        // Check if segment intersects bbox
        if segment_intersects_bbox(p1, p2, bbox) {
            // Add points, clipping to bbox boundaries
            clipped.push(clip_point_to_bbox(p1, bbox));
            clipped.push(clip_point_to_bbox(p2, bbox));
        }
    }

    clipped
}

Contains Check

impl XZBBox {
    pub fn contains(&self, point: &XZPoint) -> bool {
        point.x >= self.min_x &&
        point.x <= self.max_x &&
        point.z >= self.min_z &&
        point.z <= self.max_z
    }
}

Intersection Detection

Determining if a line segment intersects the bounding box uses the Liang-Barsky algorithm for efficient clipping.

✅ Performance Impact: Early bbox clipping reduces memory usage by up to 90% for large areas, as most OSM nodes in the data are outside the actual generation area.

Common Issues

Issue Cause Solution
World appears stretched Incorrect scale factor calculation Verify latitude is within valid range
Coordinates out of range Bbox too large for given scale Reduce bbox size or scale factor
North/South inverted Z-axis transformation error Check max_lat - lat formula
Features misaligned Inconsistent coordinate usage Ensure all points use same transformer
